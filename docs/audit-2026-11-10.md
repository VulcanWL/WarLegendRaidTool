## Open question (settle first, one test in game)
`Core.lua:741` `W.Safe` tests `v ~= nil` BEFORE `issecretvalue(v)`. The project's own recorded bug
`tools/bench/real/L6.json` (fix `a321309`, `RaidGroups.MarkOf`) says comparing a secret with nil raises "attempt to
compare" and that `type(v) == "nil"` is the nil test that works. Both cannot be right: either the central guard throws
on every real secret (the smoke model allows the nil test, so it cannot tell), or M11 below is a non-issue.
Testing `issecretvalue` first in `W.Safe` is harmless either way. UNVERIFIED.

**10/11, second pass**: `W.Safe` now tests `issecretvalue` / `canaccessvalue` first, with no comparison before (same
result for nil and plain values), and M11 the same way. The smoke model was left as it is: it lets a secret be compared
with nil on purpose (`tools/smoke.js` `smokeEqual` exempts nil, and the bench's own self-test in `scenario.lua` asserts
that `v ~= nil` passes on a secret), so it could not show this bug before and cannot show the fix now. Its rule and
the recorded bug L6 still disagree: one test in game settles which is right (still UNVERIFIED). If L6 is right, the
model's exemption should go, and every `x == nil` / `x ~= nil` on a possibly secret value becomes a bench error.
