# Full line-by-line audit — 28/10/2026 (version 1.41.5)

14 auditors read every line of the 4 shipped addons, including the embedded DoesItDie and Myslot: about 49,000
lines. The lead then checked every CRITICAL / HIGH finding, and most MEDIUM ones, in the code and in Blizzard's Forever
API docs (`tools/.cache/wow-ui-source`, build 1.60.1.70532). Focus: security (input from other players), FPS,
correctness on Forever, and the Blizzard ToS check in `WarLegendRaidTool/AGENTS.md`. Nothing was changed in the code.

Not read line by line: the upstream libraries (LibStub, CallbackHandler, HereBeDragons, LibRangeCheck, UTF8,
LibDBIcon / LibDataBroker). The lead read the Myslot decoder libraries (lua-pb `unpack.lua`, base64, CRC) and the
HereBeDragons minimap update loop: upstream code, throttled, nothing to fix.

Benches before the audit: `check.js` 0, smoke 3 / 3, open world 39 / 39, BG 15 / 15, `wow-api` 0 new.
Bench times are fengari (a simulated Lua engine, much slower than the client): use them to compare, not as real ms.

Legend: **[V]** = checked by the lead in the code; **PLAUSIBLE** = depends on how Forever behaves (test in game);
**KNOWN** = already in STATUS.md, with a new angle.

**One root cause behind both CRITICAL items and 2 HIGH ones:** Lua patterns with a repeated class followed by a
literal (`(.-)%s*=`, `([^=;]+)=`, `(%d+):(%d+)`) take quadratic or cubic time on a long field with no separator, and
`W.OnAddonLong` accepts 64 KB that compress into one ~100-byte message. Systemic fix: a per-prefix size cap in
`W.OnAddonLong` (most uses need 2-20 KB), cap every field and line before matching, split with plain `find`, and add a
"64 KB pathological message" case per prefix to `tools/smoke.js`. Add the rule to AGENTS.md.

## CRITICAL — security

1. **[V] Readiness: one ask freezes every raider's game for good** (`Readiness.lua:67`, from the ask handler
   `322-331`). `ParseLine` runs `^%s*(.-)%s*=%s*(.-)%s*$` on every line of a received ask; no limit on the list or a
   line. On a line of spaces with no "=" the cost is cubic (fengari: 400 spaces 0.16 s, 800 spaces 1.57 s); 64 KB of
   spaces is one message. A raid leader / assistant (a guild member under the default "guild") freezes every raider:
   the game must be killed. An officer pasting ~2,000 spaces in the box does it by accident.
   Fix: refuse `#list > 2000`; skip lines over ~200 bytes; split on `line:find("=", 1, true)` and trim each half.
2. **[V] Guild professions: one message freezes every guild member** (`Guild.lua:520-539`). The "D" receiver runs
   `([^=;]+)=([%d,]+)`, `([^\30\31]+)\31([^\30]+)` and `^([^:]+):(%d+):(%d+):?(%d*)$` on fields of up to 64 KB: quadratic
   (4,000 chars = 0.25 s fengari, x4 per doubling). The `count` caps are inside the loops, so they never stop a field
   with no match. Any guild member with a modified client freezes everyone who has the Guild module on, 40 times / 5 s.
   Fix: cap `#t[2]`, `#t[3]`, `#t[4]` and each item first (skills <= 64, recipes <= 20,050, links <= 4,050); split
   with `gmatch("[^;]+")` / `gmatch("[^\30]+")`, then `find("=", 1, true)` and anchored `^[%d,]+$`.

## HIGH — security

3. **[V] Myslot import: the warning misses commands that run Lua or destroy the guild** (`Myslot/gui.lua:594-621`).
   `RiskyText` flags only `/run` `/script` `/dump` and `CLICK` / `MACRO` bindings. Missed: `/tinspect` (runs
   `loadstring("return "..msg)`, Forever `SlashCommands.lua:1399-1415`); `/gleader`, `/gquit`, `/gremove` (no Blizzard
   confirmation on this build); `/gdisband` plus `/click StaticPopup1Button1` in the same macro; `/logout`, `/console`,
   lines without a slash (chat). A shared "raid profile" can put `/gleader X` on the guild master's button 1: the
   first key press hands the guild over. Fix: an allow-list like `Settings.lua` `MACRO_CMDS`; list every macro that
   uses any other command, with its line; always show "Import only a profile you trust" and the macro count.
4. **[V] Checklist: quadratic parser on received lists** (`Checklist.lua:76, 110`). `gmatch("(%d+):(%d+)")` on up to
   64 KB of digits (8,000 digits = 0.87 s fengari). "L" from a leader / assistant runs it on every raider before the
   prompt; "A" from any group member reaches the officer in the 60 s after a "Raid check"; the "A" loop does not stop
   at `MAX_ITEMS`. Fix: refuse `#t[2] > 2000`; `gmatch("[^,]+")` + anchored `^(%d+):(%d+)$`; break at `MAX_ITEMS`.
5. **[V] Skyborne: one "Q" makes every listener send up to 60 messages** (`Skyborne/Comm.lua:359-379`). `SendReply`
   re-sends every held entry of the phase, strangers' included, 9 per message, limited only by the 60-message queue.
   The "5 answers / min" cap limits the count, not the size. A stranger plants ~540 entries once, then 1 "Q" / min:
   every listener spends its channel allowance (Policy 3, rule 8). Fix: 1-2 messages per answer (own entries first,
   then the newest), only for our phase or a phase where we hold an own entry; test `answers >= MAX_ANSWERS` before
   the scan; keep a queue slot for own sightings.
6. **PLAUSIBLE — the decompression size check may not read what the decompressor reads** (`Lib.lua:271-300`, KNOWN
   bomb, new angle). `W.InflatedSize` chooses raw deflate, zlib or gzip from the first bytes; `DecompressString` is
   called with its default method, `Deflate` (enum Deflate / Zlib / Gzip, `EncodingUtilDocumentation.lua:70`). If the two
   read the same bytes differently, a crafted message passes the pre-check and inflates many MB on every guild member
   (any member: the Guild prefix uses `W.OnAddonLong`). Fix: one explicit method on both sides
   (`Enum.CompressionMethod.Deflate`), one format in `InflatedSize`, refuse a stream whose final block ends before the
   data. Part of the gated "client's own deflate" probe on 5/11.

## HIGH — correctness

7. **[V] `/wl bugs` is broken as soon as a real error exists** (`Bugs.lua:48`). `date("%Y-%m-%d %H:%M", err.time)`:
   BugGrabber stores `time` as text ("2026/11/05 20:31:12"), so `date` raises "bad argument #2". In the BugGrabbed
   callback the pcall hides it (nothing recorded); `Collect()` in the tab build is not protected, so opening the tab
   raises a new error and the box stays empty. Never exercised: the 26/10 test had 0 errors. This is the error tool for
   the 5/11 session. Fix: `type(err.time) == "number" and date(...) or tostring(err.time or "?")`; pcall `Remember`
   in `Collect`. Confirm with `/dump BugGrabber:GetDB()[1].time`.
8. **[V] PLAUSIBLE — Convert to raid from a timer / whisper will likely be refused** (`InviteTool.lua:80-88,
   162-170, 188`; INV ALL `RaidGroups.lua:1613`). `ConvertToRaid` is `HasRestrictions = true` in the Forever docs, like
   `SetRaidTarget`, which the code already knows is refused unless clicked. INV ALL and keyword invites call it from
   `W.After` / `W.OnRoster` / `CHAT_MSG_WHISPER`: the mass invite stops at 5 ("nobody joined" after 60 s), maybe with an
   "action blocked" error. `InviteUnit` has no restriction: queued invites are fine. Fix: convert in a click (the INV
   ALL click if the party has someone, else a "Convert to raid" button / `W.Confirm` when the first player joins).

## HIGH — FPS in battlegrounds

9. **[V] Roster changes re-apply every setting on all 40 buttons** (KNOWN #5, now measured as the main cost):
   `ButtonPositioning` calls `ApplyButtonSettings` on every button at each order change (`PvP/Mainframe.lua:733`);
   `UpdateAllUnitIDs` runs `UpdateUnitID` on every ally and `SortPlayers` once per changed ally (`1077-1081`); unitID,
   GUID and lead / assist count as "details changed" (`790-821`); the first scoreboard applies module settings twice
   on 40 new buttons (bench: worst entry frame 105 ms). Fix: a settings generation (re-apply only on a settings
   change), UpdateUnitID only when the unit changed, one sort, identity-only details.
10. **[V] Dispel does its work before knowing it is needed** (`PvP/Modules/Dispel.lua:470-477, 395-415`): a pcall'd
    name lookup on every group UNIT_AURA before the 0.2 s pending check; each Update anchors and builds tables and a
    signature before the "nothing changed" test; in native mode it only computes missing buffs, which 5-6 classes never
    have. Fix: a unit -> button map, return at once for a class with nothing to show, compare in place.
11. **[V] `UpdateUnitID` always runs the full chain** (`PvP/PlayerButton.lua:215-226`): UpdateAll + a UnitIdUpdate
    dispatch even when nothing changed; each ally target switch does it twice on enemy buttons (CastBar re-registers 10
    events, CrowdControl fully rebuilds its aura container, `NativeAuras.lua:264-275`). Fix: return early when unit and
    target unit are unchanged.

## MEDIUM — security

12. **[V] Guild "Q" makes the whole guild re-send its professions** (`Guild.lua:511-516`; button `G.Broadcast` 1237 /
    1321): every member broadcasts 10-25 chunks within 12 s; N answers = N² parsing; repeatable every 2 min. Fix:
    answer by WHISPER to the asker, or only if my data changed / last broadcast > 30 min; gate the button.
13. **[V] Layers registry poisoning** (`Layers.lua:73-96, 159`): remote (map, id) pairs go into the saved registry;
    300 fake map ids from one guild member = "Layer 0" everywhere for good. Fix: session table for remote readings or
    `C_Map.GetMapInfo` check; evict the least recent zone; limit new zones per sender.
14. **[V] Recruitment reminder replaces an open question** (`Guild.lua:717`; `W.Confirm`, `Lib.lua:718`): the 30 s
    timer overwrites the open prompt (Loot Council "Give X to Y?", profile import): the loot master's Yes posts the
    recruitment line in the channel and the award is lost. Fix: `W.ConfirmRemote`; skip in instances.
15. **[V] InviteTool keyword whisper: no leader check, no cooldown** (`InviteTool.lua:84-96`; module off by default,
    `guildOnly = false`, `autoRaid = true`): a stranger whispering "inv" in a loop makes us send "suggest invite" popups
    to our leader; if we lead a full party, the whisper converts it. Fix: return unless `W.CanLead()`, 30 s per sender,
    auto-convert only for guild members (and see 8).
16. **[V] PLAUSIBLE — Loot Council trade helper matches the partner by first name** (`LootCouncil.lua:1227-1229`):

    raider "Jean Dupont" placed in the window ("1 item won by Jean Dupont added"). One accept gives it to the wrong
    player and clears the debt. Fix: match with `W.SameUnit("NPC", u)` over the group, require `o.key`.
17. **Loot Council, other** (`LootCouncil.lua`): any group member's "Q" makes the ML whisper a ~64-message resync
    (3 players / 30 s) into the shared queue: the ML's next award waits ~16 s or is dropped, `awarding` clears after
    10 s, a second click awards the item twice (`674-702, 1305`). KNOWN new angle: a session starter can write 30 fake
    awards per session into every raider's saved history and push the real one out (1,000 lines) (`613-632`); record
    awards only from the real master looter. LOW: council names shown with `|c` / `|n` codes; "!sr" item id not
    bounded, scan before the rate limit, srWhisper on for everyone; CSV formula injection (`=HYPERLINK`) in exports.
18. **Skyborne** (`Comm.lua`, `Main.lua`; public channel): received traffic parsed in instances and combat, up to ~500
    `Near()` calls per entry, `covered` uncapped; held sightings saved with no global cap (up to 40,000 entries, phase
    = any digits): MB of SavedVariables after a flood; one stranger's report makes a learned pin kept forever, not
    clearable in game; PLAUSIBLE `KeepChannelLast` moves our hidden channel to a number the player types (`/5 hello`
    goes to strangers); O(pins x sightings) map redraw. Fixes: skip in instance / combat, caps, 2 senders + expiry +

19. **Imported profiles are trusted too much** (profile text is untrusted):
    - table options (`point`, `winPos`, `winScale`, `elemPos`, `framesPoint`, `auras.pos`...) stored as the profile's
      own table, scalars only type-checked, numbers up to 1e12 (`Settings.lua:162-165, 221-237`): Lua error at every
      login or window open, frames off screen. Fix: validate by kind (anchor names, offsets within ±4000, scale 0.5-2).
    - `Parse` trims with `^%s*(.-)%s*$` before the 300,000-char check: ~100 KB of blanks freezes the client on Import
      (`Settings.lua:209-211`). Fix: check `#text` first, `strtrim`.
    - PvP `TestPlayerCount` 1e9 freezes the client on Test; `Scale` 0 breaks the frames (`PvP/Main.lua:349, 820-841`).
    - KNOWN #12 new angle: kept CVars re-applied at every login with no allow-list, hidden / harmful ones included

    - the review lists 7 switches; silent: invite keyword, modules switched off, PvP click macros with `/use`

20. **Myslot, other** (`Myslot/gui.lua`, `Myslot/Myslot.lua`): `/myslot load` and `/wl myslot load` apply a saved

## ToS (Blizzard Policy + EULA + client)

No breach of Blizzard's own rules found: no automation of gameplay, no ads or donation requests, code readable,
protected actions only through secure buttons or clicks. The findings are about our stricter rules in AGENTS.md:

- **Rule 7 is wrong about invites** (the lead's own mistake when writing it): `InviteUnit` has no restriction on
  Forever; queued invites after one click are standard. Restricted (`HasRestrictions`): `ConvertToRaid`,
  `ConvertToParty`, `SetRaidTarget`, `C_ClickBindings.SetProfileByInfo`, `C_SettingsUtil.OpenSettingsPanel`. Rebuild
  the rule's list from the docs.
- Opt-in features acting on remote input or events, to write as exceptions or turn into prompts: keyword / BN whisper
  invites and accepting suggested invites (InviteTool), AutoPromote on roster events, Summon's RAID line (not
  rate-limited), Myslot import steps run from timers, Focus restoring its binding out of combat, QualityOfLife junk
  selling / quests from events, Loot Council placing owed items on `TRADE_SHOW` (the ML still accepts).
- **Policy 3 (chat)**: soft-res "Announce" posts every reserved item in one frame (50-300 RAID lines after a few
  nights) (`LootCouncil.lua:1692-1698`); Raid Buffs "Report missing" 15+ lines. Fix: a 1 line / s queue, ~20 lines max.
- Rule 10 literal failures (own data copied by hand): SimExport, Attendance CSV. Write the exception.
- Myslot export header: `myslot.net` line and the author's e-mail (rule 4 / 10 spirit): drop the line.
- Readiness can still read a raider's exact gold in ~6 asks (8 "gold N" lines per ask); Checklist answers exact bag
  counts to any group lead with no opt-out: privacy, not ToS.
