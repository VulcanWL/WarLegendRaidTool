A team of 14 reviewers read the code in parallel; each one read every line of its slice. Together that is about
62,000 lines: the 4 shipped addons (embedded Myslot and DoesItDie included), the Dev addon, `tools/` and the CI.
11 reviewers each had a slice of files. Three worked across all files: window UI / UX, code architecture, and a
security red team.

The lead checked the following in the code, and in Blizzard's Forever API docs where needed
(`tools/.cache/wow-ui-source`, build 1.60.1.70532):
- every HIGH;
- the top finding of each reviewer.

Nothing was changed in the code.

Focus: security (input from other players, pasted text), FPS, correctness on Forever, design (code and window), and
the Blizzard ToS check in `WarLegendRaidTool/AGENTS.md`. Items already fixed or listed in
`docs/audit-2026-10-28.md` and the AGENTS.md "Accepted exceptions" are not repeated. Fixes from 28-29/10 that are
incomplete or broke something are flagged **REGRESSION**: about 2,160 lines changed since the 28/10 audit.

Not read line by line:

  lua-pb / base64 / crc32 decoder loops were checked for bounds.

## Verdict

**No CRITICAL finding: 7 HIGH, about 45 MEDIUM, the rest LOW.**

**What holds:**
- The architecture is sound:
  - one trust point for addon messages (`Dispatch`);
  - every receiver bounded before its patterns;
  - `W.Measure` on every handler, so `/wl perf` sees everything;
  - an off switch per file;
  - the load-on-demand split.
- No message from another player reaches a protected action, an invite, a mark, a loot gift or a public chat line by
  itself.
- No first-name spoofing in the trust checks.
- Escape codes are filtered in every receiver.

**The weak spots:**
1. **Imported profiles.** `Settings.lua` checks the *types* of imported values, not the *values*. One pasted profile
   can cover the screen with battleground buttons or break frames at every login (HIGH 3).
2. **Trust edges.** Loot Council lets any assistant lock the master looter out (HIGH 1). Name helpers fall back to a
   first-name match on the "First-Surname" form (HIGH 2).
3. **Regressions from the 28/10 fixes:**
   - PvP unit cache: the wrong ally's health is shown (HIGH 5);
   - chat lines sent from timers (HIGH 6);
   - Myslot confirmation (HIGH 4);
   - RaidCooldowns under the GCD (15);
   - drag and drop (28);
   - "Ask the guild" (45).
4. **Rule 7.** Several restricted calls run outside the click. They wait for the 5/11 test or for your decision
   (HIGH 6).
5. **The bench is greener than the code.** Secret values are modelled for 3 of about 20 Forever predicates;
   `format("%s", nil)` passes; addon replies never fail the run (HIGH 7).

## HIGH

**1. Loot Council: any raid assistant locks the master looter out for 10 minutes. [V]**
- Where: `WarLegendRaidTool_Raid/LootCouncil.lua:502-507`, also 177-179, 487-492, 793, 1840-1848.
- Cause: `Receive.S` keeps the first session it sees for 600 s:
  `if S and not SameName(S.mlFull, full) and GetTime() - S.started < 600 then return end`.
  `MayStart` accepts any leader or assistant (`W.IsGroupLead`). "Test session (your gear)" sends its session to the
  RAID.
- Scenario A, no ill intent: an assistant clicks Test mid-raid and closes the window.
  - Three minutes later the master looter opens the boss.
  - His own warning (`OpenWarning`, added 28/10) says "the new one replaces it for everyone". He clicks Start and
    sees "Loot session started".
  - No vote window opens anywhere, his own client included.
- Scenario B, on purpose: a whispered "S" from an assistant (`WHISPERED.S`, l.793) takes one chosen raider out of
  every council session. Their votes never arrive and they show as "no addon".
- Fix:
  - `LootAuthority(full)` always replaces a session; anyone replaces a test session.
  - Accept a whispered "S" only within 40 s of my own "Q". Move `local askedAt` (l.695) above `Receive.S`: a
    reference there today would read a global.
  - Send test sessions `LOCAL` while in a group.
  - Make `OpenWarning` name the open session's owner.
- Related LOW: one "S" makes 40 raiders reply "K" (l.502-524): ignore a new "S" from the same sender within 5 s.

**2. Name trust: a "First-Surname" name falls back to a first-name match. [V code, input format PLAUSIBLE]**
- Where: `Core.lua:918-928` (`W.GuildMember`), `Lib.lua:517-541` (`W.UnitByName`).
- Cause: both test `W.HasFullPart(name)` on the raw name. On Forever that looks for the space. `W.FullName` handles
  the hyphen form "First-Surname" (Core.lua:569), but `HasFullPart("Arthur-Bogus")` is false. The code then returns
  the guild's only "Arthur" (`guildByShort`).
- Callers that pass raw event names:
  - InviteTool keyword invite with "guild only", and its auto-convert to raid (`InviteTool.lua:86, 98`);
  - QualityOfLife auto-accept of invites (`QualityOfLife.lua:56-64`, which also ignores `inviterGUID`);
  - InviteTool's suggested-invite accept (`InviteTool.lua:134`);
  - the `!sr` gate (`LootCouncil.lua:1512`).
- `Dispatch` is safe: it passes the normalised full name.
- Scenario: a stranger who shares a first name with a guild member whispers the invite keyword and gets invited.
  Or his invite is auto-accepted.
- Fix:
  - `local full = W.FullName(name)`, then `W.HasFullPart(full)`, in both helpers (2 lines).
  - Decide invites by GUID (`IsGuildMember(guid)`, `C_FriendList.IsFriend(guid)`).
- Test: `/run print(WLRT.GuildMember("<first name only one guild member has>-Zzz") ~= nil)` prints true = bug.

**3. Imported profiles: values are never validated. One shared profile can freeze or break the client. [V]**

Root cause: `Settings.lua` Apply checks types only (numbers up to 1e12, strings up to 20,000), and the scalar branch
accepts any type when the local value is nil. The 28/10 fix (lot C) covered table positions and the PvP Scale /
TestPlayerCount only.

- **PvP sizes and colours.** `Height = 3000` / `Width = 1e6` make 40 secure buttons cover the screen and catch every
  click. `BarColor = {"x"}` errors inside `ButtonPositioning`, so the remaining buttons are never placed
  (`WarLegendRaidTool_PvP/Main.lua:305-327`; the PvP merge in `Settings.lua:296-309` is type-only).
  - **Correction (lead, while fixing):** reviewer 8 reported a client freeze through `config.ActivePoints = 1e9`
    (also `UpdatePeriod`, `RelativeFrame`, `Parent`). That path cannot be reached: `BuildProfile` rebuilds the button
    config from `Data.defaultSettings` and reads only a fixed list of saved fields (Scale, Width, Height, PowerHeight,
    X / Y, Range, BarColor, Style, Modules on / off...). Only those fields needed clamping.
- **Positions and scales.**
  - `GoodPoint` checks types, not shape: `{}` and `{"TOP"}` pass. That gives `SetPoint(nil…)` errors in CapTimers,
    CCAlert, DangerAlert, DuelTimer, GYTimer, MoveFrames and AuraTracker (`Settings.lua:161, 242-253, 290-291`).
  - The scalar positions (`point`, `relPoint`, `x`, `y`, `scale`, `size`) of MarksBar, CombatTimer, MoneyGoal,
    Upgrades, RaidCooldowns, CCAlert and Transports are unchecked: `SetScale(0)`, an "XYZ" anchor, or offsets of 1e12.
  - `raidCooldowns` is missing from `STRING_POINT`, so even a normal profile places that window on a mixed anchor.
  - `guildPositions.size = 4000` makes guild pins 4000-px buttons that catch world clicks.
- **AuraTracker** (`AuraTracker.lua:93, 431`):
  - `auras.tankNames = "a,a,a…"` (10,000 names) costs about 1.6 M API calls per Apply, and Apply runs on every roster
    change.
  - `auras.custom` runs `gsub("%s+$")` on 20 KB of spaces: the quadratic trim the 28/10 `W.Trim` fix missed. It runs
    at every raid-addon load, even with the module off.
- **Table contents.** `TABLE_FIELDS` contents are stored unchecked (`Settings.lua:287-288`). `guild.msgs = {{}}` makes
  the Recruitment tab and each reminder error. A `classes.leaders` string with `|T…|t` shows live.
- **Data leaking into profiles.**
  - Transports' measured schedules (`c<id>/a<id>/o<id>`) are exported. After an import they are re-shared to the guild
    as my own observations (`Settings.lua:183-199`, `Transports.lua:163-164, 188`).
  - `interfaceOptions.cvars` is replaced whole: the player's own kept CVars are dropped.
- **The confirmation hides changes.**
  - `RISKY` misses `loot.srWhisper`, `summon.enabled` / `say`, `qol.acceptResurrect`, `loot.councilExtra` /
    `councilRank`, and the four default-on guild share flags.
  - `Review` counts modules switched *off*, never *on* (`Settings.lua:367-375, 426-433`).
  - Scenario: the player had the guild map off; after the import it broadcasts their position every 5 s, and the
    confirm said nothing.
- **Import in combat.** It drops the PvP part silently (`W.LoadPvP` refuses), yet the player is told "imported".
- **Fix: one validation pass, about 40 lines.**
  - Per-field validators by name in Apply: anchors in `ANCHORS`, offsets ±4000, scale 0.5-2.5, size 8-200,
    strings ≤ 255 and `W.Plain` for names.
  - Pick the point check by value type (and drop `STRING_POINT`).
  - Turn `SKIP_PREFIX` into patterns.
  - Clamp the saved PvP fields in `BuildProfile`: Width 50-600, Height 8-100, PowerHeight 1-30, colours 0-1,
    position, range.
  - AuraTracker: `W.Trim`, stop at 2 tanks, cap the lists.
  - Extend `RISKY` and `Review`.
  - Add a "PvP numbers / scalar positions" case to the smoke paste phase. The fake `SetPoint` accepts any anchor today
    (`tools/smoke/wow.lua:291`).

**5. PvP regressions of the 28/10 P2: the wrong ally is shown in battlegrounds. [V]**
- **Departed button.** The group-unit button cache (`Main.lua:1345-1355`, with `Mainframe.lua:848-851`): in combat a
  departed ally's button cannot be removed and keeps `unitID = "raid3"`. The cache check `button.unitID == unitID and
  IsShown()` passes. Until combat ends, raid3's health, death and target go to the departed player's frame, and the
  ally who moved there freezes.
  Fix: `wipe(groupUnitButtons)` at each roster read; clear `unitID` of status-2 buttons before the combat queue.
- **Re-targets every read.** `changed = allyButton.unit ~= unitID` (`Mainframe.lua:1086-1108`) stays true for the
  whole fight, because `.unit` is only updated out of combat. Every roster read in combat re-runs the
  targeting reset for each moved ally. That flips enemy units and runs `UpdateAll` plus the `UnitIdUpdate` dispatch
  for up to 39 allies. This is the likely cause of the bench's worst frame (`timer Main.lua:1815`, 11.7 ms).
  Fix: compare with the previous `unitID`.
- **Full health bars.** `ApplyAllSettings` sets every bar to full (`HealthBar.lua:149-151`). The new early-out in
  `UpdateUnitID` removed the refresh that followed. After an option change or a combat-deferred setup, a dead ally
  shows a full bar until the next `UNIT_HEALTH`. Fix: `UpdateAll` at the end of `ApplyButtonSettings`.
- **Marks.** Raid marks disappear on `ApplyAllSettings` and are no longer re-read (`RaidTargetIcon.lua:67`,
  `PlayerButton.lua:223-228`).

## MEDIUM — security

**8. No trust table in `Dispatch`. [V]** (red team)
- **Battleground strangers act as leader.** `INSTANCE_CHAT` is accepted (`Core.lua:348`, `LootCouncil.lua:792`) although
  nothing of ours sends on it, and the raid addon loads in battlegrounds. The battleground's random leader can:
  - open loot and vote windows on every WLRT user mid-fight;
  - show Raid Buffs popups with **no rate limit** (`RaidBuffs.lua:212-238`);
  - show Checklist and preset prompts;
  - read bag counts.
- **Raid prefixes on GUILD.** They are accepted there although nothing sends them. One `WLRT_INSQ` on GUILD loads the
  raid addon on the whole guild and makes every grouped member broadcast (`RaidInspect.lua:225-228` has no group
  check).
- **Buffered before the check.** `WLRT_PROF` chunks from non-guild senders are buffered and inflated (about 1.7 MB per
  prefix) before `Guild.lua:523` drops them.
- **Prompts.** Checklist and preset prompts do not use `W.Sender` (no "not in guild" tag); the preset prompt shows a
  first name only (`Checklist.lua:93-99`, `RaidGroups.lua:829-860`).
- **Fix:** a `TRUST` table checked in `Dispatch` before any handler or buffer:
  - "guildchan": PROFILE, LAYER, MINO, TRANSP, GuildMapEx1;
  - "guild": PROF;
  - "group": VERQ, INSQ, INSD, DUR, CD2, RDYA;
  - "raid", refused on GUILD and in PvP: LC, CON, BUFF, RG, RDYQ.
  - Also: drop `INSTANCE_CHAT`, allow one Raid Buffs popup per 10 s, and use `W.Sender` with full names in both
    prompts.
  - Draft (red team). Replace `Core.lua:348`, call `Trusted` before the handler and before the load-on-demand branch
    (about l.499 and l.529). Leader / assistant checks stay in the handlers (they need the unit):
    ```lua
    local GROUP_CHANNELS = { RAID = true, PARTY = true, GUILD = true, OFFICER = true } -- nothing of ours sends INSTANCE_CHAT
    local GUILD_CH = { GUILD = true, OFFICER = true }
    local TRUST = {
        WLRT_PROFILE = "guildchan", WLRT_LAYER = "guildchan", WLRT_MINO = "guildchan", WLRT_TRANSP = "guildchan",
        GuildMapEx1 = "guildchan", WLRT_PROF = "guild",
        WLRT_VERQ = "group", WLRT_INSQ = "group", WLRT_INSD = "group", WLRT_DUR = "group", WLRT_CD2 = "group",
        WLRT_RDYA = "group",
        WLRT_LC = "raid", WLRT_CON = "raid", WLRT_BUFF = "raid", WLRT_RG = "raid", WLRT_RDYQ = "raid",
    }
    local function Trusted(prefix, channel, full)
        local t = TRUST[prefix]
        if not t then return true end -- WLRT_VER: group or guild, as today
        if t == "guildchan" then return GUILD_CH[channel] or false end
        if t == "guild" then return W.GuildMember(full) ~= nil end
        if GUILD_CH[channel] then return false end -- raid prefixes never come from the guild channel
        if channel == "WHISPER" and not W.UnitByName(full) then return false end
        return t ~= "raid" or not W.InPvP()
    end
    ```

## MEDIUM — correctness

**15. RaidCooldowns: ready cooldowns vanish raid-wide during a boss. [V-doc] REGRESSION (A1 partial)**
- Where: `RaidCooldowns.lua:76-83, 146-149, 351-352`.

## Code architecture

**Health: sound, keep it.**
- One event frame with lazy registration.
- `W.Measure` attribution.
- An off switch per file.
- Load on demand with replay.
- One message trust point.
- Boundary helpers used widely (`W.Safe`, `W.Plain`, `W.Finite` / `W.Int`, `W.Trim`, `W.CutUTF8`).
- A lockdown-aware queue.
- Centralised name identity.
- `check.js`'s cross-file guards.
- Highest upvalue count: 38.
- No `Core.lua` split is needed.

**Two weak spots:**
- `Settings.lua` is the only place that knows every module's saved shape, and it is opt-out. That is where HIGH 3
  comes from.
- Sibling modules re-grow the same helper, so each fix lands 2-5 times and the copies drift.
