## Bug trouvé (1)

### Ligne 80 : condition inversée dans le minuteur de 5 minutes

```lua
local mark = wbAt
W.After(300, function() if wbAt ~= mark and not fought then WorldBossOver() end end)
```

**Explication** : `mark` est une copie de `wbAt` prise à l'engagement. Au bout de 300 s, le minuteur ne doit agir que si aucun nouvel engagement n'a eu lieu entre-temps, donc si `wbAt == mark`. Avec `~=`, c'est l'inverse :

- Dans le cas normal (un seul boss ciblé), `wbAt == mark`. Le test est faux et le filet de sécurité « 5 minutes si le combat n'a jamais commencé » ne se déclenche jamais. `worldBoss` reste à `true` jusqu'au prochain changement de zone, et le log reste actif.
- Si le joueur a ciblé un autre boss monde entre-temps, `wbAt ~= mark`. L'ancien minuteur appelle alors `WorldBossOver()` sur la nouvelle session, qui est peut-être encore valide.

**Correction** :

```lua
local mark = wbAt
W.After(300, function()
    if worldBoss and wbAt == mark and not fought then WorldBossOver() end
end)
```

Le test `worldBoss` évite un appel inutile si la session est déjà terminée. `WorldBossOver()` vérifie déjà `worldBoss` et l'état de combat.
