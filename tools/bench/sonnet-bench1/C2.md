## 2. Code à ajouter dans Focus.lua

### a) Constante des défauts

Remplacer la ligne 54 (dans `W.OnReady`) :

```lua
local DEFAULTS = { enabled = false, modifier = "shift", button = "1" }

W.OnReady(function()
    db = W.DB("focus", DEFAULTS)
end)
```

`DEFAULTS` doit être déclarée avant `W.OnReady` (par exemple juste après `local db`). C'est une table de scalaires, donc compatible avec `W.DB`.

### b) Fonction de reset et commande slash

À placer après le bloc `W.RegisterModule` (fin du fichier). `Apply`, `db`, `L` et `DEFAULTS` sont des locals déjà visibles à cet endroit.

```lua
local function ResetDefaults()
    if not db then return end
    -- on met à jour la table existante (ne pas la remplacer : W.DB peut en garder la référence)
    for k, v in pairs(DEFAULTS) do db[k] = v end
    if InCombatLockdown() then
        -- Apply() sort silencieusement en combat ; PLAYER_REGEN_ENABLED le rappellera
        print("|cff33ff99WLRT|r " .. L("Focus settings reset. They will apply after combat."))
        return
    end
    Apply()
    print("|cff33ff99WLRT|r " .. L("Focus settings reset to default."))
end

W.slash.focusreset = ResetDefaults

W.AddFR({
    ["Focus settings reset to default."] = "Réglages du Focus remis par défaut.",
    ["Focus settings reset. They will apply after combat."] = "Réglages du Focus réinitialisés. Ils s'appliqueront après le combat.",
})
```

Remarques :
- **Combat** : `Apply()` contient déjà `InCombatLockdown()` et sort sans rien faire. Les attributs sécurisés des frames et `ClearOverrideBindings` ne sont donc pas touchés en combat. Je teste quand même en amont pour afficher le bon message. `db` est remis à zéro tout de suite, et `Apply` est rappelé par `PLAYER_REGEN_ENABLED`, déjà enregistré.
- **Traduction** : `L("...")` est appelé dans la fonction (donc après `ADDON_LOADED`), jamais au chargement du fichier. Il s'agit bien d'appels `L("...")`, pas `L["..."]`. Le français est dans `W.AddFR` du même fichier.
- **Panneau ouvert** : si le panneau Focus est affiché, les boutons Modificateur et Clic gardent leur ancien texte. `sync` est local à la construction du panneau et `mod:SetScript("OnShow", sync)` ne rafraîchit que le bouton `mod`. Deux options :
  - le plus simple : ne rien faire, le texte sera rafraîchi à la réouverture ;
  - ou remonter `sync` dans une variable locale du fichier (`local syncUI`) appelée depuis `ResetDefaults` avec `if syncUI then syncUI() end`.
- **Bug existant à noter** : `mb` n'a pas de `OnShow = sync`. Avec `mod` seul, le bouton « Click » peut rester périmé à la réouverture. Ajouter `mb:SetScript("OnShow", sync)` serait cohérent, mais hors périmètre de la demande.
- **Bug existant à noter** : dans `Apply`, `SetOverrideBindingClick(btn, ...)` utilise `btn`, qui n'est non nil que parce que `Btn()` a été appelé juste avant. Ça fonctionne, mais `Btn()` serait plus sûr.
- **API** : aucune API WoW incertaine n'est utilisée (`InCombatLockdown`, `print`, `pairs`). `W.slash` est supposé exister d'après les règles du projet.

   - Passer le client en anglais : le message est en anglais.
   - Vérifier qu'il n'y a aucune erreur Lua (BugSack ou `/console scriptErrors 1`).
4. Contrôle des règles : pas de `goto`, de `//`, d'opérateur bit à bit ni de `table.unpack` dans le code ajouté.
