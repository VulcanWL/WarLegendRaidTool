## Bugs trouvés

### Bug 1 : `W.Unpack`, ligne 153 : les champs vides sont perdus

Le motif `([^%^]+)%^` exige au moins un caractère. Un champ vide (un `nil` converti en `""` par Pack) n'est donc jamais capturé.

Exemple : `W.Pack("a", nil, "c")` donne `"a^^c"`. `Unpack` renvoie `{"a", "c"}` au lieu de `{"a", "", "c"}`. Les champs suivants sont décalés. Le contrat `W.Unpack(W.Pack(a, b, c))` redonne les champs, nil -> "" n'est pas respecté.

Correction :

```lua
function W.Unpack(msg)
    local t = {}
    for v in (msg .. "^"):gmatch("([^%^]*)%^") do t[#t + 1] = v end
    return t
end
```

Avec `*`, chaque match consomme le `^` final. Il n'y a donc pas de boucle infinie en Lua 5.1, et les champs vides sont conservés.

### Bug 2 : `W.Pack`, lignes 146-147 : les `nil` ne sont pas traités de façon fiable

`local t = { ... }` suivi de `for i = 1, #t` utilise l'opérateur `#` sur une table qui peut contenir des trous. La longueur n'est pas fiable avec des `nil`.

Exemple : `W.Pack("a", "b", nil)` peut donner `#t == 2`. Le dernier champ vide est alors perdu, et `Unpack` renvoie 2 champs au lieu de 3. Dans les cas avec un `nil` au milieu, la longueur peut aussi être fausse selon la taille du tableau.

Correction : utiliser `select("#", ...)`.

```lua
function W.Pack(...)
    local n = select("#", ...)
    local t = {}
    for i = 1, n do
        local v = select(i, ...)
        if v == nil then v = "" end
        t[i] = (tostring(v):gsub("%^", ""))
    end
    return table.concat(t, "^")
end
```

Les parenthèses autour de `gsub` écartent son second retour (le nombre de remplacements). Ce n'est pas un bug dans une affectation simple, mais c'est plus sûr.

### Note sur Unpack et les messages vides

Avec la correction du bug 1, `W.Unpack("")` renvoie `{""}`, soit un champ vide. Cela correspond à `Pack(nil)`, donc c'est cohérent.
