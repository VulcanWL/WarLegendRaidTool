## Bugs trouvés

### 1. Ligne 26 : opérateur `//` (Lua 5.1) : erreur de syntaxe, le fichier entier ne se charge pas

`secs // 60` n'existe pas en Lua 5.1. Le fichier ne compile pas, donc tout le module CombatTimer est absent. C'est aussi une violation explicite des règles du projet.

Correction :
```lua
return string.format("%d:%02d", math.floor(secs / 60), secs % 60)
```

### 2. Ligne 59 : le chrono de boss ne s'arrête jamais sur `ENCOUNTER_END`

`if isEncounter and encounterEnd then return end` fait quitter `Stop(true)` sans rien arrêter. Le chrono de boss ne peut donc plus s'arrêter que par `PLAYER_REGEN_ENABLED`.

Si `PLAYER_REGEN_ENABLED` arrive pendant que l'encounter est encore en cours (mort du joueur, sortie de combat brève, ou `PLAYER_REGEN_ENABLED` reçu avant `ENCOUNTER_END`), la ligne 58 fait retourner `Stop(false)`. L'événement `ENCOUNTER_END` ne rattrape alors rien à cause de la ligne 59. `startAt` reste défini, le ticker tourne indéfiniment, et le chrono continue de compter après le combat. De plus, les `Start(false)` suivants sont ignorés (`startAt` non nil).

Correction : supprimer la ligne 59. Le test de la ligne 58 suffit, car il ne bloque que `Stop(false)` quand l'encounter est en cours.
```lua
local function Stop(encounterEnd)
    if not startAt then return end
    if isEncounter and not encounterEnd and IsEncounterInProgress and IsEncounterInProgress() then return end
    Update()
    startAt = nil
    isEncounter = false
    if ticker then ticker:Cancel(); ticker = nil end
    if db.hideOOC then W.After(5, function() if not startAt then ApplyVisibility() end end) end
end
```
J'ai ajouté `isEncounter = false`. `Start` le réécrit de toute façon à la ligne 49, donc c'est une précaution et non un bug.
