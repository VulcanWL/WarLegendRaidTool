# Trace de CombatTimer.lua (enabled = true, bossOnly = false)

État initial : `startAt = nil`, `isEncounter = false`, `ticker = nil`.

## 1) Entrée en combat contre un trash : `PLAYER_REGEN_DISABLED` -> `Start(false)`
- Les gardes (lignes 42-43) passent : le module est activé, il n'y a pas de PvP, pas d'overlap, et `bossOnly` est faux.
- `startAt` est nil, donc on ne prend pas la branche « déjà en cours ».
- Ligne 49 : `startAt = T0 = GetTime()` et `isEncounter = false`.
- `Update()` affiche 0:00, puis `C_Timer.NewTicker(1, Update)` crée le ticker (ligne 51).
- **État : `startAt = T0`, `isEncounter = false`, `ticker = <actif>`.**

## 2) Le boss est engagé : `ENCOUNTER_START` -> `Start(true)`
- `startAt` est non nil, donc on entre dans le bloc des lignes 44-48.
- `encounter and not isEncounter` est vrai : `startAt, isEncounter = GetTime(), true` (ligne 46).
- **Le chrono est donc remis à 0:00 et devient un chrono de boss.** `Update()` est appelé immédiatement, puis `return`.
- Le `return` empêche la création d'un second ticker. Il n'y a pas de doublon, c'est le même ticker qui continue.
- **État : `startAt = T1` (nouveau), `isEncounter = true`, `ticker` inchangé (actif).**

## 3) Le joueur meurt et sort de combat : `PLAYER_REGEN_ENABLED` -> `Stop(false)`
- `startAt` est non nil, donc on ne sort pas à la ligne 56.
- Ligne 58 : `isEncounter` est vrai, `encounterEnd` est faux, et `IsEncounterInProgress()` renvoie vrai car la rencontre continue. Donc `return`.
- **Le chrono ne s'arrête pas à la mort.** Rien n'est modifié : le ticker continue et l'affichage continue de s'incrémenter.
- Si le joueur ressuscite et rentre en combat, `Start(false)` est appelé. `startAt` est non nil et `encounter` est faux, donc on `return` sans rien changer.
- **État inchangé : `startAt = T1`, `isEncounter = true`, `ticker` actif.**

## 4) Fin de la rencontre : `ENCOUNTER_END` -> `Stop(true)`
- Ligne 58 : `encounterEnd` est vrai, donc la condition est fausse et on ne retourne pas.
- Ligne 59 : `not isEncounter` est faux (c'est un chrono de boss), donc on ne retourne pas.
- `Update()` affiche la valeur finale (durée du boss, `GetTime() - T1`).
- `startAt = nil`, puis `ticker:Cancel(); ticker = nil`.
- Si `hideOOC` est actif, un `W.After(5, ...)` rappelle `ApplyVisibility()` 5 s plus tard. Le chrono est alors masqué si `startAt` est toujours nil.
- **État final : `startAt = nil`, `isEncounter = true` (non remis à false), `ticker = nil`.**

## Réponse
- **Redémarrage :** oui, une seule fois, à `ENCOUNTER_START`. Le chrono du trash est abandonné et le chrono repart de 0:00 en mode boss. Il ne mesure donc que la durée du boss, pas le trash + le boss.
- **Mort :** non, le chrono ne s'arrête pas. Le `Stop(false)` déclenché par la sortie de combat est ignoré tant que `IsEncounterInProgress()` est vrai.
- **Arrêt :** uniquement à `ENCOUNTER_END`, via `Stop(true)`. Le ticker est annulé à ce moment-là.

## Remarques
- `isEncounter` reste à true après l'arrêt. Ce n'est pas gênant, car `Start` le réécrit à la ligne 49 au prochain démarrage. En revanche, si `Start(true)` est appelé alors que `startAt` est nil, la ligne 49 est utilisée directement.
- Si `IsEncounterInProgress` n'existe pas dans le client (la garde `IsEncounterInProgress and ...` est faussée), la ligne 58 ne retourne jamais. Le `Stop(false)` de l'étape 3 passerait alors la ligne 59, car `isEncounter` est vrai. Le chrono s'arrêterait donc à la mort, et le `ENCOUNTER_END` suivant ne ferait rien (`startAt` est nil). Le comportement décrit ci-dessus suppose que cette API existe.
- À la fin de la rencontre (kill), le joueur peut encore être en combat. Le chrono s'arrête quand même à `ENCOUNTER_END`, et le `PLAYER_REGEN_ENABLED` qui suit est ignoré (`startAt` est nil).
