## Ce qui se passe

`W.DB` fait `W.db[key]`. Or `W.db` n'est assigné que dans le handler `ADDON_LOADED` (`W.db = WarLegendRaidToolDB`, ligne 561). Au chargement du fichier (niveau fichier, hors fonction), `W.db` vaut `nil`.

1. **Au chargement** : `W.db[key]` indexe `nil`, donc l'erreur Lua « attempt to index field 'db' (a nil value) ». Le fichier s'arrête à cette ligne. `local db` n'est jamais assigné et tout ce qui suit dans le fichier (fonctions, `W.On`, `W.slash`, `W.AddFR`) n'est jamais défini. Le module est donc mort, avec une erreur visible dans BugSack ou l'écran d'erreur Lua.
2. **Ensuite** : rien ne rattrape l'erreur. `ADDON_LOADED` s'exécute plus tard pour les autres modules, mais pas pour ce fichier, qui a déjà échoué. Le module n'a ni données, ni handlers, ni commande.

## Problèmes

- **Crash au chargement** : `W.db` est nil avant `ADDON_LOADED`. C'est le problème principal.
- **Violation de la convention** : les données doivent être initialisées dans `W.OnReady(function() db = W.DB(...) end)`, qui est exécuté après le chargement des données sauvegardées. `OnReady` diffère l'appel si `W.db` n'existe pas encore (ligne 517), ou l'exécute tout de suite si `W.db` existe déjà.
- **Défaut non scalaire** : `history = {}` est une table. `W.DB` ne gère que les scalaires (`type(t[k]) ~= type(v)`). Si `history` manque, `t.history` reçoit la table `{}` du littéral, qui est partagée par référence. Si elle est du mauvais type, elle est remise au défaut. Ce défaut peut marcher par hasard, mais il sort de la règle « scalaires uniquement » et l'initialisation d'une sous-table doit être faite à part. La réparation du mauvais type ne vaut que pour le type `table`, pas pour son contenu.
- **Aucune migration** : si le format des données change plus tard, il faut passer par `W.Migration`.

## Écriture correcte

```lua
local W = WLRT
local L = W.L
local db

W.OnReady(function()
    db = W.DB("loot", { enabled = true })
    if type(db.history) ~= "table" then db.history = {} end
end)

-- Événements : le handler ne tourne que si W.Allowed() (pas de always)
local h = W.On("CHAT_MSG_LOOT", function(msg)
    if not db or not db.enabled then return end
    db.history[#db.history + 1] = msg
end, false, true) -- inactive = true : démarre éteint

-- Activation si besoin :
-- W.Activate(h, true)
```

Points à respecter :
- Les défauts de `W.DB` ne contiennent que des scalaires. La table `history` est créée à part, avec une vérification de type, comme `W.db.ui.off` dans Core.lua (ligne 568).
- `db` n'est lu que dans des fonctions ou handlers, jamais au niveau du fichier. Les handlers vérifient `db` ou ne s'exécutent qu'après `OnReady`.
- Les textes visibles passent par `L("English text")` à l'intérieur de fonctions, jamais au niveau du fichier. Le français va dans `W.AddFR({...})` du même fichier.
- Si le module ajoute une commande, il faut `W.slash.loot` dans le module, une entrée dans la liste HELP de Core.lua avec son texte français, et une ligne dans le tableau « Commandes » de README.md.
- Aucune API WoW incertaine sans garde, et `InCombatLockdown()` d'abord pour toute frame sécurisée.
- Vérifier avec `node tools/check.js`, puis copier avec `bash tools/sync.sh`. Pas de bump de version sans demande.
