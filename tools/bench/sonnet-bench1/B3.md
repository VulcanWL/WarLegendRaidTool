# Bugs trouvés dans Focus.lua

## Bug 1 : ligne 75, `L["..."]` au lieu de `L(...)`
`L` est une fonction. `L["Focus is not available on this client."]` indexe la fonction, ce qui lève l'erreur « attempt to index local 'L' (a function value) ». Le panneau plante quand `FocusUnit` est absent (`AVAILABLE == false`). Cela viole aussi la règle du projet.

```lua
W.Label(p, L("Focus is not available on this client."), "GameFontDisable"):SetPoint("TOPLEFT", 16, -44)
```

## Bug 2 : lignes 59-60, `L()` appelé au chargement du fichier
`BUTTONS` est construit au niveau du fichier avec `L("Left")`, etc. La langue n'est connue qu'à `ADDON_LOADED`, donc ces textes restent en anglais, ou `L` peut ne pas être prêt. La règle impose d'appeler `L()` dans les fonctions de construction ou les handlers.
`MODS` n'est pas traduit non plus, car `Label` traduit via `L(e[1])`. Il faut donc stocker les clés anglaises brutes et laisser `Label` traduire (ce qu'il fait déjà). Cela corrige aussi la double traduction de `BUTTONS`.

```lua
local MODS = { { "Shift", "shift" }, { "Alt", "alt" }, { "Ctrl", "ctrl" } }
local BUTTONS = { { "Left", "1" }, { "Right", "2" }, { "Middle", "3" }, { "Mouse 4", "4" }, { "Mouse 5", "5" } }
```

## Bug 3 : lignes 32-51, `Apply()` sans test `InCombatLockdown()`
`Apply` est appelée depuis `PLAYER_ENTERING_WORLD`. Cet événement peut survenir en combat après un `/reload`. Elle est aussi appelée par les callbacks de l'UI, y compris en combat. Elle fait `SetAttribute` sur des frames sécurisées (TargetFrame, PlayerFrame, etc.), `ClearOverrideBindings` et `SetOverrideBindingClick`, ce qui est refusé ou produit une erreur « ADDON_ACTION_BLOCKED » en combat. De plus, `Btn()` peut créer le bouton sécurisé en combat (ligne 39). L'état serait alors faux, `prevKey` étant remis à nil alors que rien n'a été appliqué.
Correction : tester en tête de fonction. `PLAYER_REGEN_ENABLED` est déjà branché et rappellera `Apply` après le combat.

```lua
local function Apply()
    if not db then return end
    if InCombatLockdown() then return end   -- réappliqué à PLAYER_REGEN_ENABLED
    ...
```

## Bug 4 : aucun `W.AddFR({...})` dans le fichier
Tous les textes visibles passent par `L(...)` : "Left", "Right", "Middle", "Mouse 4", "Mouse 5", "Modifier:", "Click:", "Enable click-to-focus", "Focus is not available on this client.", "Click the buttons to change them...", "Settings apply out of combat.". Le fichier n'a aucune traduction française, ce qui viole la règle « le français va dans W.AddFR du même fichier ». L'interface reste donc en anglais pour les joueurs francophones.

```lua
W.AddFR({
    ["Left"] = "Gauche", ["Right"] = "Droit", ["Middle"] = "Milieu",
    ["Mouse 4"] = "Souris 4", ["Mouse 5"] = "Souris 5",
    ["Modifier:"] = "Modificateur :", ["Click:"] = "Clic :",
    ["Enable click-to-focus"] = "Activer le clic pour focus",
    ["Focus is not available on this client."] = "Le focus n'est pas disponible sur ce client.",
    ["Click the buttons to change them. E.g. Shift + left-click on a mob or a frame = focus.\n"] =
        "Cliquez sur les boutons pour les modifier. Ex. Maj + clic gauche sur un mob ou un cadre = focus.\n",
    ["Settings apply out of combat."] = "Les réglages s'appliquent hors combat.",
})
```

La forme exacte (table clé/valeur ou autre) doit suivre celle de `W.AddFR` dans le projet. Elle n'est pas visible ici.
