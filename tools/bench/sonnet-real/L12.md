CAUSE 1: ligne 495 (avec lignes 480-481, 486-487) — `Zone()` est branchée sur ZONE_CHANGED_NEW_AREA, qui se déclenche aussi en changeant de sous-zone dans le même champ de bataille. Elle remet à zéro les échantillons d'estimation (`samples`), `scoreWidgets`, et arrête les barres "win", "cap:" et "flag". Il ne faut réinitialiser que lorsque l'instance change réellement.
CORRECTIF:
```lua
local lastInst
local function Zone(force)
    local inst = InstanceID()
    if not force and inst and inst == lastInst then
        -- même champ de bataille : seulement rafraîchir la carte
        if capOn then
            mapID = C_Map and C_Map.GetBestMapForUnit and W.Safe(C_Map.GetBestMapForUnit("player")) or mapID
        end
        return
    end
    lastInst = inst
    -- ... corps actuel de Zone() inchangé (lignes 477-492) ...
end
W.On("PLAYER_ENTERING_WORLD", function() if anchor then StopMatching("cap:") end; Zone(true) end)
W.On("ZONE_CHANGED_NEW_AREA", function() Zone() end)
```
CAUSE 2: ligne 494 — PLAYER_ENTERING_WORLD réinitialise toujours, ce qui est correct pour une vraie entrée, mais aussi lors d'un écran de chargement dans la même instance ; `Zone(true)` y suffit.
