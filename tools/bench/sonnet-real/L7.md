CAUSE 1: ligne 401 — Le motif `%d+%s*/%s*%d+` accepte n'importe quel widget texte contenant "n/n" ; dans un champ à drapeaux (Warsong, etc.), les deux premiers widgets qui correspondent (par orderIndex) ne sont pas forcément les scores Alliance/Horde (captures x/3 : max 3, autres compteurs), et la ligne 396 peut aussi retenir une barre double qui n'est pas le score. Les scores et le max sont alors mal lus et l'estimation est absurde. Dans Arathi, les compteurs ressources x/1500 sont les seuls à correspondre.
CORRECTIF:
```lua
        if UI.GetIconAndTextWidgetVisualizationInfo then
            local okT, t = pcall(UI.GetIconAndTextWidgetVisualizationInfo, id)
            local text = okT and t and W.Safe(t.text)
            if type(text) == "string" then
                local cur, mx = text:match("(%d+)%s*/%s*(%d+)")
                if cur and tonumber(mx) >= 100 then -- score de ressources, pas un compteur de drapeaux x/3
                    texts[#texts + 1] = id
                end
            end
        end
```
CAUSE 2: ligne 403 — la fonction ne renvoie rien si l'on ne trouve pas exactement deux compteurs ; pour les BG à drapeaux, il faudrait désactiver l'estimation de temps (ESTIMATOR_ZONES) plutôt que d'extrapoler des captures discrètes.
